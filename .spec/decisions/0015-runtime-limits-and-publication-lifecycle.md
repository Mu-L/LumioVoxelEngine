# 0015 · 宿主预算可配置，发布历史不无限保留，摘要缓存不改变编码

- 日期:2026-09-06
- 状态:生效

## 背景

World 创建将回执容量固定为 16，完成项不回收，真实第 17 笔不同事务被拒绝。
发布器还保存每次发布的 token ID，且在写锁内销毁旧根与 pin。
不可变 Section sidecar 的摘要会被重复展开、压紧、编码计算。

## 决策

- 用 `WorldLimits` 注入宿主策略，`create` 使用有限的开发默认值；不添加 wire 字段。
  Revision pin 至少为 2，允许当前根与下一密封根并存。回执与查询容量必须为正。
- 已完成回执不因容量压力而静默淘汰。公开占用量，容量满拒绝新请求，但保持旧请求幂等。
  耐久检查点、重放窗口与回执安全回收是未完成的跨域工作，不以扩大容量冒充解决。
- 删除无界 `used_ids` 集合。令牌不可复制、调用者不可构造、seal 一次性，以及完整
  owner/generation/base 检查共同维护一次性发布；外部资源 Handle 的生命周期规则不变。
- 交换完整发布根后先释放写锁，再销毁旧根/pin。实例 generation 计数耗尽后永久拒绝，不能绕回重用。
- payload 构造验证页与 sidecar 一致后，缓存已经密封的内容摘要。旧摘要字节、Debug
  输出与存档元数据编码不变。本条没有把 Debug 身份升级成规范持久身份。
- 目录 overlay 从完整目录起步，仅替换改动项，不根据 revision map 重建目录。
  BTreeMap 首次 COW 仍为 O(N)，发布根身份仍有全局工作，不声称 O(改动量)。

## 后果

新增真实连续修改、满载重试、伪造同 ID 请求拒绝、目录 presence 保留、COW 摘要与
计数耗尽测试；Linux/Windows/macOS 运行同一工作区测试。移动真机、长期性能、完整
冷恢复与收紧所有发布者消费者入口仍需独立验收。
